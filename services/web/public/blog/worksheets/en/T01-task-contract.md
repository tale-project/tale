# Agent task contract

Copy this document for one bounded assignment. Replace the bracketed fields, remove inapplicable rows, and keep the completed contract with the task. An assignment is ready when the owner can explain the input, expected result, permitted actions, and review criteria without referring to an unwritten conversation.


## Filled excerpt — synthetic handbook audit

These invented records show a completed portion of the contract and its handoff. They illustrate reasoning; no agent run or product outcome was observed.

| Contract field | Filled example |
| --- | --- |
| Separate contribution | Compare handbook r6 with approved product reference r12; the other audit examines customer questions |
| Integration owner | One designated handbook editor owns the proposed revision |
| Conflict | Handbook r6 says every teammate can invite users; reference r12 requires an administrator; support note S-08 reports a standard account inviting someone |
| Source judgment | The handbook is being checked; S-08 establishes an unverified reported experience; r12 governs documented permissions |
| Proposed correction | “An administrator sends the invitation” |
| Unresolved question | Product owner must determine whether S-08 involves a different role, configuration, or a defective reference |
| Integration readiness | Partial: do not present an explanation for S-08 as established; keep the affected section blocked if the owner cannot confirm the rule |

If r13 replaces r12, recheck the permission finding before accepting the correction. The customer-question audit may remain usable because its inputs did not change. Partial acceptance must be allowed by the agreed process; otherwise the deliverable waits.
