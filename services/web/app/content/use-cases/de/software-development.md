Beschreibe die Website, App oder das interne Werkzeug, das dein Team braucht. Organisiere dann die Arbeit vom Briefing über Umsetzung, Tests und Review bis zur Release-Vorbereitung. In Tale arbeiten technische und nichttechnische Teammitglieder über Projektaufgaben und Diskussionen mit Agenten zusammen.

## Das gewünschte Ergebnis klären, bevor Code entsteht

Lege ein Projekt mit Problemstellung, Referenzmaterial, Repository-Kontext und Abnahmekriterien an. Teile die Arbeit in überschaubare Aufgaben auf: einen Prototyp, eine Funktion, eine Fehlerkorrektur, Tests oder Dokumentation. Weise Agenten und Reviewer zu, starte die Aufgaben und verfolge den Fortschritt auf dem Board.

Ein Agent kann in seiner konfigurierten Sandbox Code schreiben und ausführen, über Tests berichten und Ergebnisse abliefern. Aktionen im Repository hängen von den GitHub-Werkzeugen, Zugangsdaten und Berechtigungen ab, die der Agent erhält. Verschiedene Agenten können unabhängige Aufgaben im Rahmen der eingerichteten Kapazität bearbeiten. Abhängigkeiten und die Integration muss dein Team weiterhin planen.

## Beispiel: ein internes Anfrageportal bauen

1. **Die Aufgabe beschreiben.** Ein Teammitglied aus dem Fachbereich erklärt, wer Anfragen stellt, welche Angaben nötig sind und wie das Team sie bearbeiten soll.
2. **Eine klar begrenzte Änderung umsetzen.** Ein Agent arbeitet am Formular und an der Validierung, mit passend eingerichtetem Repository und Werkzeugen.
3. **Das Ergebnis prüfen.** Prüfe die laufende Anwendung, Codeänderungen und Testnachweise. Erwähne den zugewiesenen Agenten in einem Aufgabenkommentar, um Überarbeitungen anzufordern.
4. **Den Release vorbereiten.** Ergänze bei Bedarf Aufgaben für Dokumentation, Migration oder Deployment. Veröffentliche über den eingerichteten Release-Prozess deines Teams.

Eine abgeschlossene Aufgabe führt nicht automatisch zu einem Merge oder Deployment. Nichttechnische Teammitglieder können Ziele definieren und das Verhalten beurteilen; vor dem Produktivbetrieb braucht es auch eine angemessene technische Prüfung.

## Vorhandene Agentenzugänge nutzen, wo sie unterstützt werden

Tale koordiniert Agentenarbeit rund um das Projekt. Wähle eine unterstützte Laufzeit und passende API- oder Abo-Zugangsdaten. Vorhandene Abos lassen sich nutzen, wenn die jeweilige Laufzeit sie unterstützt. Die [Laufzeitdokumentation](https://docs.tale.dev/de/platform/agents/harnesses) erklärt die Kompatibilität und den Unterschied zwischen direkten Anbieteraufrufen und Tales erfasstem Gateway-Verbrauch.

Wenn du vor allem interaktiv im Code arbeitest, kann dein Codeeditor Teil des Prozesses bleiben. Tale hilft, wenn das gesamte Team Aufgaben vergeben, Richtung vorgeben und mehrere Agentenaufgaben gemeinsam prüfen möchte.

Entdecke [Projekte](/de/platform/projects), lies den [Ablauf für Aufgabenreviews](https://docs.tale.dev/de/platform/projects/task-automation) oder [buche eine Demo](/de/request-demo) mit einer echten Aufgabe aus deinem Backlog.
