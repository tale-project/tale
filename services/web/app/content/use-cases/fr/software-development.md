Décris le site, l’application ou l’outil interne dont ton équipe a besoin, puis organise le travail du brief à la préparation de la mise en production, en passant par le développement, les tests et la revue. Dans Tale, collègues techniques et non techniques collaborent avec les agents au moyen de tâches et de discussions.

## Clarifier le résultat attendu avant d’écrire du code

Crée un projet avec le problème, les références, le contexte du dépôt et les critères d’acceptation. Découpe le travail en tâches assez petites pour être vérifiées : prototype, fonctionnalité, correction, tests ou documentation. Affecte les agents et les responsables de revue, démarre les tâches, puis suis l’avancement sur le tableau.

Un agent peut écrire et exécuter du code dans sa sandbox configurée, expliquer les tests effectués et rendre des livrables. Les opérations sur le dépôt dépendent des outils GitHub, des identifiants et des permissions accordés. Plusieurs agents peuvent traiter des tâches indépendantes selon la capacité configurée ; ton équipe doit toujours prévoir les dépendances et l’intégration.

## Exemple : créer un portail de demandes interne

1. **Définir le besoin.** Une personne du métier explique qui dépose les demandes, quelles informations sont nécessaires et comment l’équipe doit les traiter.
2. **Réaliser une modification délimitée.** Un agent travaille sur le formulaire et sa validation, avec un dépôt et des outils configurés pour cette tâche.
3. **Vérifier le résultat.** Examine l’application en fonctionnement, les modifications du code et les preuves de test. Mentionne l’agent affecté dans un commentaire de la tâche pour demander des corrections.
4. **Préparer la livraison.** Ajoute les tâches de documentation, de migration ou de déploiement nécessaires. Publie selon le processus de ton équipe.

Terminer une tâche ne fusionne ni ne déploie automatiquement le code. Les collègues non techniques peuvent définir les objectifs et vérifier le comportement ; une mise en production demande aussi une revue technique adaptée.

## Utiliser tes accès existants lorsqu’ils sont compatibles

Tale coordonne le travail des agents autour du projet. Choisis un environnement d’exécution pris en charge et des identifiants API ou d’abonnement compatibles. Tu peux utiliser un abonnement existant si l’environnement le permet. La [documentation des environnements d’exécution](https://docs.tale.dev/fr/platform/agents/harnesses) explique la compatibilité et la différence entre les appels directs au fournisseur et les appels mesurés par la passerelle Tale.

Si ton activité principale est l’édition interactive de code, ton éditeur peut rester dans le processus. Tale est utile quand toute l’équipe doit attribuer le travail, donner des indications et examiner plusieurs tâches d’agents ensemble.

Découvre [les projets](/fr/platform/projects) et [la revue des tâches](https://docs.tale.dev/fr/platform/projects/task-automation), ou [demande une démo](/fr/request-demo) avec un élément réel de ton backlog.
