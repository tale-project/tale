### R1-1 · forms · `FORM-F6`

**Surface** `POST https://tale.dev/api/forms/submit` · **Severity** `blocker`
(recorded as `crit` in the old table)

Production returns HTTP **503** `{"ok":false,"error":"Service not
configured"}` (2026-07-06 honeypot probe) — `WEB_DISCORD_WEBHOOK_URL` is
unset, so **every** contact and demo submission fails. The UI now shows the
permanent **This deployment has no form delivery configured yet, so your
message was not sent. Please use another channel to reach the team.**
(`forms.errors.notConfigured`; the body code was `Service not configured`
before the `not_configured` rename). Set `WEB_DISCORD_WEBHOOK_URL` +
`WEB_FORMS_REQUIRED=true` in the deployment; `/api/health` should report
`checks.forms.ok: true` after fix. 2026-08 status:
`forms.errors.notConfigured` + the health check have shipped in the codebase —
**re-probe production (FORM-F6)** to confirm whether the env var is now set
before keeping this open

### R1-2 · seo · `SEO-B1`

**Surface** `https://tale.dev/nope-not-a-route` · **Severity** `bug` (recorded
as `med` in the old table)

Soft 404 was live on 2026-07-06. Fixed in branch: prerendered `/404` + shared
server serves HTTP 404 when `dist/404/index.html` exists. Re-verify on next
production deploy; docs site parity tracked in
[#2620](https://github.com/tale-project/tale/issues/2620)

### R1-3 · accessibility · `A11Y-A2`

**Surface** `https://tale.dev/` (all pages) · **Severity** `polish` (recorded
as `low` in the old table)

Unlabelled nav landmarks persist after the 2026-07 site rewrite (2026-08 code
audit): the header's primary `<nav>`
(`packages/ui/src/components/site/site-header.tsx`, desktop nav) and the
mobile drawer `<nav id="mobile-nav">` both have no accessible name, while all
five footer column navs are labelled (`site-footer.tsx` wraps each column in
`<nav aria-label={col.heading}>`) — screen-reader users can't tell the nav
landmarks apart

### R1-4 · accessibility · `A11Y-A2`

**Surface** footer (all pages) · **Severity** `polish` (recorded as `low` in
the old table)

NEW 2026-08: the footer's fifth column — the Ruler GmbH postal-address block —
is also wrapped in `<nav aria-label>` although it contains **no links**
(`links: []`, only an `<address>` body); an addressless-of-purpose nav
landmark is noise for AT users — it should be a plain labelled region, not a
`<nav>`

### R1-5 · forms · `FORM-F5`

**Surface** `/de/contact`, `/fr/contact` · **Severity** `polish` (recorded as
`low` in the old table)

The privacy-policy checkbox link is a hard `<a href="/legal/privacy-policy">`
— on localized forms it leaves the locale tree (English legal page) and
bypasses the SPA router
