# Workspace panel — Manual Test Plan

> **Purpose**: Exercise the unified chat side panel — the Canvas (agent-written
> files, code-run output, the file viewers), the read-only Workspace-files
> explorer, the Live-browser stream with human takeover, the Research-plan pane,
> and the chat input's Sandbox pill. All content in this panel is produced by agent
> tool calls; the mock stack now synthesizes the sandbox-free ones
> (`file_write`, `update_todos`), so the Canvas and Research-plan panes are
> coverable in **mode A** (#2688), while `run_code` output, the Workspace-files
> explorer, and the Live browser still need mode B / B+sandbox. The
> conversation surface itself is [chat.md](chat.md)'s.

## Scope & routes

| Surface                     | Route                              |
| --------------------------- | ---------------------------------- |
| Chat panel (all four panes) | `/dashboard/{org}/chat/{threadId}` |

(The panel has no route of its own — it appears inside a thread once a pane has
content; `{threadId}` is produced by sending a first message.)

## Prerequisites

Bring the stack up and sign in per [SETUP.md](SETUP.md). **Mode A** is the
hermetic mock stack. It now scripts the sandbox-free workspace tool calls via
keyword triggers (`lib/mocks/overrides/canned.ts`): a message containing
**`e2e:filewrite`** makes the mock write a set of Canvas files (md/mmd/html/svg/py
under `/user/output/`), and **`e2e:plan`** seeds the Research-plan todos — so
F1–F5 and F20 run in mode A. Cases that need a real run or the Docker runtime
(`run_code` output, the explorer, the live browser) still need **mode B** — a
live provider plus a platform agent that has the `file_write` / `run_code` tools
(the built-in assistant ships with them, per
`builtin-configs/agents/chat/assistant.json`). Explorer, live-browser, and
sandbox-pill cases additionally need the Docker sandbox runtime: **mode
B+sandbox** = the full Docker stack (NOT `dev:fast`, NOT
`TALE_DEV_SKIP_DOCKER=1`) plus an **external agent** (Settings → Agents, type
**External agent**, `settings.agents.form.agentType.externalLabel`; default
runtime **Claude Code**).

> **B+sandbox setup gotchas (verified live):** (1) the per-thread runtime image
> `tale-sandbox-runtime:latest` is **not public and not a compose service** — on
> a fresh checkout it is absent and the first external-agent turn 502s with
> "Unable to find image locally". Build it first with
> `bun scripts/ensure-sandbox-runtime-image.ts` (from the repo root; it bundles a
> headless browser + fonts, so the first build takes several minutes). The
> spawner (`tale-sandbox` container, `:8003`) inspect-gates the local image, so
> once built it runs without a registry. (2) Verified live: the sandbox **spawns
> correctly** (container healthy, Claude Code runs inside) but **external-agent
> turns currently error on the model path** — see Issues #2. That blocks the
> _content/flow_ half of the cases below (files the agent would write, a page it
> would browse, a plan it would produce); the _structural_ half (panel/pane
> presence, tab and control accessible names, empty states, toggles) still
> verifies and is marked per case.

> **Agent note**: panes register into one right panel with three states —
> absent (no content), a 48 px minimized strip, and a maximized tab bar. All
> visible pane bodies stay **mounted** — inactive ones carry the `hidden`
> attribute — so assert visibility, not DOM presence. Wait on structure, not
> timing: the Canvas is ready when its file explorer — a vertical `role="tree"`
> named **Canvas** (`chat.canvas.title`, `canvas-file-tree.tsx`) — shows the
> written file's row; a streaming write shows a **Writing…** meta that
> disappears when the file lands; the Live browser is ready when the polite
> `role="status"` text
> **Live** (`chat.liveBrowser.streaming`) appears. Turn completion is the
> Send⇄Stop toggle from [chat.md](chat.md).
