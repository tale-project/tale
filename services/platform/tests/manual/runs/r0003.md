## Scope

This exploratory round used the open-source platform to verify documentation
for members, editors, developers and administrators. It covered real UI
interactions, persistent results, a complete API chat example and automation
execution. The model gateway supplied deterministic responses; database,
indexing, object storage, authorization and workflow state were real.

## Baseline

There was no untouched-tree full-catalogue baseline. The task began by fetching
main into a new worktree and creating an isolated stack. The machine's global
Bun 1.3.10 failed two sandbox daemon tests even in isolation; all 159 passed
with the repository's pinned Bun 1.4.2. Closing gates use that pinned runtime.
The original checkout and unrelated running services were left intact.

## Findings

| ID | Severity | Box | What |
| --- | --- | --- | --- |
| R3-1 | `blocker` | `APV-F1` | Invalid or unavailable approval-policy files could erase restrictions for a new internal write. |
| R3-2 | `bug` | Automation run input | Required automation inputs had no entry field in Test run or Run live. |
| R3-3 | `bug` | `APV-F1` | The pending-card parser rejected UUID approval IDs, hiding both decision controls. |
| R3-4 | `bug` | Automation run history | A pending run's null completion timestamp rendered January 1, 1970. |
| R3-5 | `bug` | Project agent model selection | Searching by the model's API ID returned no option when its display name differed. |
| R3-6 | `bug` | `KNOW-F3` | Knowledge entries displayed Not indexed despite completed indexing, and document hints did not refresh their query. |
| R3-7 | `docs` | Settings and governance copy | SSO, personalization, skill invocation and audit-verification descriptions promised behavior the current implementation does not provide. |

### R3-1 · Approval policy must fail closed

New decisions now read the existing strict, uncached configuration path. Invalid
YAML, invalid schema, or an unavailable configuration mount cannot substitute
an unrestricted default. Existing pending decisions retain their authority.
The live probe corrupted only its own isolated policy, verified zero effects,
and restored the original policy state.

**Pinned by:** `backend/domains/approvals/gate.policy.test.ts`, the existing
gate/policy tests, and a real local workflow probe.

### R3-2 · Supply and review automation input

The existing confirmation dialog now collects JSON against the saved test
version or the deployed live version. It preserves the selected project scope,
shows the schema, validates without runtime code generation, and sends the
original JSON. Live execution retains its confirmation and reviewed version.

**Pinned by:** `app/features/automations/components/automation-detail.test.tsx`
and the real github-triage-issues mock run.

### R3-3 and R3-4 · Render native waiting runs

The old alphanumeric parser excluded hyphens in native UUIDs. It now recognizes
the actual approval ID, while null timestamps and null details no longer render
a false finish date or an empty alert. The original waiting run was reopened,
rejected through the UI and verified failed without effects.

**Pinned by:** `app/features/automations/components/run-detail.test.tsx`.

### R3-5 · Find a model by its API ID

The existing searchable selector now checks the model ID as well as its label
and provider. Selecting the result still saves the matching provider/model pair.

**Pinned by:** `app/features/projects/components/project-agent-dialog.test.tsx`.

### R3-6 · Reflect actual knowledge indexing

The knowledge-entry list now joins the tenant-scoped document and current file
metadata, preserving legacy entries and keyset pagination. Document hints also
invalidate the corresponding organization's knowledge-entry queries. The real
Postgres regression checks every status, failure details, foreign metadata
isolation and pagination; a browser-created entry reaches Indexed without a
reload.

**Pinned by:** `backend/domains/knowledge_entries/indexing.integration.ts` in
the backend integration gate, and `app/lib/backend/use-backend-hints.test.tsx`.

### R3-7 · Describe implemented controls

Localized UI descriptions and the docs now match the actual SSO organization
picker, separate import consent, stored personalization preferences, advisory
skill invocation metadata, and bounded native audit verifier. The source audit
also removed unsupported guarantees from operator guides while retaining the
company certifications confirmed by the product owner.

## Not reached

No sandbox was connected to the isolated stack, so task-agent work completion
and a real coding-agent session were not proved. Mock replies do not establish
model quality or real-provider retrieval behavior. Vendor OAuth, live mail,
production backups/restores, audit-export continuation, hardware microphone
capture, real-device PWA installation and enterprise deployment operations were
not completed. Videos were excluded. Other manual-suite boxes remain unrun.

## Verdict

The observed runtime defects were fixed, regression-tested and re-driven in
the isolated stack. Documentation distinguishes the verified workflows from
operator prerequisites and the environment-specific outcomes above. The round
supports the documentation change; it does not claim exhaustive platform QA.

The closing repository check passed all 43 tasks with Bun 1.4.2 and two
concurrent tasks. An earlier concurrent run missed a filesystem-watcher event;
the unchanged watcher passed all nine tests in isolation and in the closing
gate. The real-Postgres knowledge-indexing regression, manual-test guard,
unused-code check and SAST passed. Independent review found no blocking issue
in the changed code.
