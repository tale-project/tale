# Settings — Manual Test Plan

> **Purpose**: Exercise the personal and workspace settings — account profile,
> personalization/preferences, organization (incl. members), teams, branding,
> integrations (incl. the MCP endpoint section), the API surfaces (REST keys, WebDAV),
> AI providers, token sources, skills, sandboxes, data residency/deployment, and
> Enterprise SSO. Governance has its own guide ([governance.md](governance.md));
> security/2FA/passkeys/sessions live in [auth.md](auth.md). All tabs save via the
> global Save/Discard bar in the settings header — verify by reload, never by toast.

## Scope & routes

The settings rail groups pages as **Personal** (Account, Preferences,
Environment), **Organization** (Organization, Teams, Skills, AI providers, Token
sources, Integrations, Branding, Sandboxes, Governance, Enterprise SSO) and
**Development** (API, Data residency). The rail label for the
`/settings/personalization` route is **Preferences** (`navigation.personalization`).

`…/governance/logs` (covered in [governance.md](governance.md));
`…/settings/agents` → `/dashboard/{org}/agents` (leaves Settings — the org
agent roster lives under [agents.md](agents.md), not Settings).

## Prerequisites

Bring the stack up and sign in per [SETUP.md](SETUP.md) as an owner/admin (many
Organization-group tabs are role-gated — Admin for Organization/Branding/
Enterprise SSO/Data residency, Admin-or-Developer for Integrations/API keys/
Skills; see [auth.md](auth.md) RBAC). Data residency editing is further restricted
to the operator emails listed in `TALE_DEPLOYMENT_CONFIG_ADMINS` in the
deployment `.env`. Restore any toggled setting after the run.

> **Agent note**: each tab saves via the global **Save** / **Discard** bar in the
> settings header (`common.actions.save` / `common.actions.discard`), NOT a
> per-form button (exceptions: API keys, Token sources, and WebDAV use their own
> create dialogs/sheets). Verify a persisted write by reloading and reading the
> field/row back, never by the transient success toast. The settings **index**
> client-side-redirects to a permission-appropriate page on desktop and shows a
> list on mobile; on a bare `/settings` hit the main panel can be momentarily
> blank while the redirect resolves — that is expected, not a render error.
