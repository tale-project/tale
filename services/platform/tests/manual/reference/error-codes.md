# Error-surface provocation map

Which error each surface can produce, and how to reach it deliberately. Used by
the suites when a box says "expect the error state", and as the checklist for
"should this even be reachable from here?".

Add a row when a new error becomes reachable, with the shortest path that
provokes it and the recovery the surface offers.

## Reachable from the UI

| Surface                                                                               | How to reach it                                                                                                                                                                                                                                                                              |
| ------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Sandbox limits exceed deployment capacity (`sandboxes.limits.totalExceedsDeployment`) | In Settings > Sandboxes, edit the three limits so their total exceeds deployment capacity. The total and error update; saving stays blocked until the total fits. If the operator lowers capacity after the page loads, saving also catches the new limit.                                   |
| Sandbox deployment capacity unavailable (`sandboxes.limits.capacityUnavailable`)      | In a disconnected sandbox-service test stack, raise a limit in Settings > Sandboxes so the total grows. The page explains that lowering still saves and that infrastructure data must be refreshed before raising; reconnect and use Refresh. Lowering a limit in that state saves normally. |

## Reachable on the API surface only

Never a rendered message — seeing one of these in the UI is itself a bug.

| Failure                                                                          | Where it shows up                                                                                                                                                                                                                                                                                                                                            |
| -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `SANDBOX_QUOTA_EXCEEDS_DEPLOYMENT` (400)                                         | Save a `sandbox_quota` policy whose three limits add up above the spawner's current `maxSessions`. The error data includes `total` and `maxSessions`; the existing policy remains unchanged. The UI renders a localized explanation, never the raw code.                                                                                                     |
| `SANDBOX_CAPACITY_UNAVAILABLE` (503)                                             | Save a `sandbox_quota` policy whose total is HIGHER than the saved total while the authoritative deployment capacity cannot be read. A total that does not grow saves without the capacity. The existing policy remains unchanged; retry after the service recovers.                                                                                         |
| `CHAT_MODEL_UNKNOWN` / `CHAT_MODEL_AMBIGUOUS` (400)                              | `POST /api/v1/threads/{id}/messages` with a `model` that `GET /api/v1/models` does not list, or one listed under two providers with no `providerSlug`. Nothing is queued; the 202 of a good send names the resolved `providerSlug`.                                                                                                                          |
| `CHAT_TURN_NOT_RUNNING` (404)                                                    | `DELETE /api/v1/threads/{id}/generation` while the poll says `idle`. During a turn the same call answers 202 `cancelling`.                                                                                                                                                                                                                                   |
| `CHAT_TURN_IN_PROGRESS` (409) on delete                                          | `DELETE /api/v1/threads/{id}` while a turn runs; cancel the turn first, then the delete answers 204.                                                                                                                                                                                                                                                         |
| `KNOWLEDGE_ENTRY_SUPERSEDED` (409)                                               | `PATCH /api/v1/knowledge-entries/{id}` on an entry a newer version replaced; edit the active one. Deleting a superseded entry removes that row only; deleting the active entry removes the chain and drops the document's passages from the search corpus at once.                                                                                           |
| `DOCUMENT_STALE` (409)                                                           | `PATCH /api/v1/documents/{id}` with an `expectedUpdatedAt` older than the row's `updatedAt` (read the document, patch it once, then patch again with the first `updatedAt`). Nothing is written; the 200 of a good patch carries the new `updatedAt`.                                                                                                        |
| `DOCUMENT_HAS_KNOWLEDGE_ENTRY` (409)                                             | `DELETE /api/v1/documents/{id}` — or a `PATCH` of `title` / `content` — on the `documentId` a knowledge entry answers (`sourceProvider: knowledge`); `data.entryId` names the entry. A folder or metadata patch of the same document goes through.                                                                                                           |
| `FILE_NOT_FOUND` / `FOLDER_NOT_FOUND` (404) on delete                            | `DELETE /api/v1/projects/{id}/files/{documentId}` for a Hub document, a content-only document or another project's file; `DELETE /api/v1/projects/{id}/folders/{folderId}` for a Hub folder or another project's folder. The row stays.                                                                                                                      |
| `PROJECT_KEY_TAKEN` (409)                                                        | `POST /api/v1/projects` with an explicit `key` another project holds. A derived key that collides is re-derived instead.                                                                                                                                                                                                                                     |
| `PROJECT_KEY_INVALID` (400)                                                      | `POST /api/v1/projects` with an explicit `key` of one character, seven characters or a symbol (`"a-b"`); the door caps the length at 6 and the domain refuses the shape. Nothing is created.                                                                                                                                                                 |
| `PROJECT_DUPLICATE_EXTERNAL_ID` (409) for a normalized twin                      | `POST /api/v1/projects` twice with the same `externalItemId` once in NFD (`acme-cafe` + U+0301) and once in NFC (`acme-café`), or once padded with spaces: the second answers 409, and `GET /api/v1/projects?externalItemId=` finds the one project under either spelling.                                                                                   |
| `INVALID_QUERY` on a padded lookup (400)                                         | `GET /api/v1/projects?externalItemId=%20%20` (blank once trimmed), or `?externalItemId=x&limit=5` — a lookup takes no page parameter. `GET /api/v1/projects?archived=nope` names `archived`.                                                                                                                                                                 |
| `ROLE_FORBIDDEN` (403) on the project lifecycle                                  | `PATCH /api/v1/projects/{id}` `{"archived": true}` or `DELETE /api/v1/projects/{id}` with an editor's key; an admin's key archives (the project leaves `GET /api/v1/projects`, appears under `?archived=only`, refuses writes with `PROJECT_ARCHIVED`) and deletes (204, then 404).                                                                          |
| `PROJECT_HAS_BOUND_AUTOMATIONS` (409)                                            | `DELETE /api/v1/projects/{id}` while `GET /api/v1/projects/{id}/automations` lists an installed automation; `data.automations` names it. Uninstall it (`DELETE /api/v1/projects/{id}/automations/{name}`), then the delete answers 204.                                                                                                                      |
| `PROJECT_HAS_PROTECTED_RECORDS` / `PROJECT_LEGAL_HOLD` (409)                     | `DELETE /api/v1/projects/{id}` (cascade, the default) on a project holding an approved controlled record, or a document under a legal hold; `{"mode": "detach"}` releases documents instead and passes the record guard. The app's delete dialog answers the same codes.                                                                                     |
| `FOLDER_NAME_TAKEN` (409)                                                        | Rename a project folder (app) to a sibling's name in another case. Through REST it answers only when the re-read after a lost create race finds nothing (practically never): `POST /api/v1/projects/{id}/folders` with `{"name": "INBOX"}` beside `inbox` answers 200 `created: false` with the stored spelling.                                             |
| `FOLDER_NAME_INVALID` / `FOLDER_DEPTH_EXCEEDED` (400)                            | `POST /api/v1/projects/{id}/folders` with `{"name": "a/b"}`, `"."` or `".."`; or with a `parentId` twenty levels deep. A name over 128 characters or of only whitespace is `INVALID_BODY` naming `name`.                                                                                                                                                     |
| `UPLOAD_POLICY_REJECTED` / `UNSUPPORTED_FILE_TYPE` at the mint (400)             | `POST /api/v1/projects/{id}/uploads` with `{"fileName": "x.bin"}` (format allowlist) or a name the org's `upload_policy` extension/MIME rules refuse — nothing is presigned, no bytes travel; the same body without `fileName` mints, and the bind refuses instead.                                                                                          |
| `BLOB_NOT_FOUND` (404)                                                           | `POST /api/v1/projects/{id}/files` binding a handoff whose presigned `url` was never PUT to; the intent is rolled back, so PUT the bytes and bind the same `uploadId` again.                                                                                                                                                                                 |
| `OBJECT_STORE_UNCONFIGURED` (503)                                                | Any mint, bind or `…/content` read on a deployment with no object store connected (`OBJECT_STORE_*` unset, no org bucket).                                                                                                                                                                                                                                   |
| `PROJECT_AGENT_SECRET_UNKNOWN` (400)                                             | `POST` or `PUT /api/v1/projects/{id}/agents…` with `secrets: ["NO_SUCH_SECRET"]`; `data.secrets` names it and nothing is written. The app's agent dialog prunes the same name silently.                                                                                                                                                                      |
| `PROJECT_AGENT_STALE` (409)                                                      | `PUT /api/v1/projects/{id}/agents/{agentId}` with an `expectedUpdatedAt` older than the agent's `updatedAt` (read it, save once, save again with the first stamp); `data.updatedAt` is the current one and nothing is written.                                                                                                                               |
| `PROJECT_NOT_FOUND` before `TASK_NOT_FOUND` (404)                                | `GET /api/v1/projects/<unknown>/tasks/<unknown>` answers `PROJECT_NOT_FOUND`; the same task id under a real project answers `TASK_NOT_FOUND`.                                                                                                                                                                                                                |
| `TASK_ARCHIVED` (403)                                                            | `POST /api/v1/projects/{id}/tasks/{taskId}/comments` or `…/start` on a task archived in the app; the task and its comments still read as 200.                                                                                                                                                                                                                |
| `INVALID_BODY` for a padded task key (400)                                       | `POST /api/v1/projects/{id}/tasks` with `externalId: "   "` — `data.issues` says `must not be blank`; `"  case-001  "` is accepted and re-picks the task created as `case-001`.                                                                                                                                                                              |
| `WEBSITE_DOMAIN_NOT_CRAWLABLE` (400)                                             | `POST /api/v1/websites` naming `localhost`, a link-local or RFC 1918 host, or a cloud metadata address, with `TALE_ALLOW_PRIVATE_CRAWL_HOSTS` unset.                                                                                                                                                                                                         |
| `WEBSITE_DOMAIN_NOT_CRAWLABLE` (400) for a resolved address                      | `POST /api/v1/websites` naming a public hostname whose DNS answer is loopback, private or metadata (`127.0.0.1.nip.io`, `10.0.0.1.nip.io`, `169.254.169.254.nip.io`) with `TALE_ALLOW_PRIVATE_CRAWL_HOSTS` unset; the sentence names the resolved address and no row is created. A name DNS cannot answer yet registers and fails on its first scan instead. |
| `WEBSITE_DOMAIN_IMMUTABLE` (400)                                                 | `PATCH /api/v1/websites/{id}` with a `domain` other than the stored one (`renamed.example`, or the stored host as a URL with a path). The stored value itself, in any case, is accepted, and the patch answers 200 with the website.                                                                                                                         |
| `CONTACT_DUPLICATE_EMAIL` / `CONTACT_DUPLICATE_EXTERNAL_ID` (409)                | `POST /api/v1/contacts` (or a `PATCH` onto the key) with the email of a live contact in another case (`Ada@Example.COM` beside `ada@example.com`), or its `externalId`; a trashed contact frees both keys. In `POST /api/v1/contacts/bulk` the twin fails its own row under `errors[].errorCode` and the rest land.                                          |
| `CONTACT_STALE` / `PRODUCT_STALE` (409)                                          | `PATCH /api/v1/contacts/{id}` or `PATCH /api/v1/products/{id}` with an `expectedUpdatedAt` older than the row's `updatedAt` (read it, patch once, patch again with the first stamp); nothing is written, and the 200 of a good patch carries the new `updatedAt`.                                                                                            |
| `CONTACT_IDENTITY_REQUIRED` (400)                                                | `PATCH /api/v1/contacts/{id}` with `{"name": null, "email": null, "externalId": null}` (or `""` for each) on a contact that carries only those; clearing one while another stays answers 200, and a patch that leaves all three alone always passes.                                                                                                         |
| `DUPLICATE_PRODUCT_NAME` / `DUPLICATE_PRODUCT_EXTERNAL_ID` (409)                 | `POST /api/v1/products` with the name of an existing product in another case (`widget` beside `Widget`), or its `externalId`; a `PATCH` renaming onto either answers the same. The app's create and edit dialogs map the name twin to their own message.                                                                                                     |
| `INVALID_BODY` on a free-form field (400)                                        | `POST /api/v1/contacts` with `metadata` (or `address`) nested nine levels deep, holding more than 500 keys in total, or over 64 KiB of JSON; `data.issues[0].path` names the path (`metadata.a.a.…`). The same on `/api/v1/products` and `/api/v1/documents`.                                                                                                |
| `INVALID_BODY` on a typed product field (400)                                    | `POST /api/v1/products` with `currency: "ZZZ"` (or `"123"`, `"$"`), or `imageUrl: "javascript:alert(1)"`; `usd` is accepted and stored as `USD`. A blank `name` (`"   "`) on create or patch answers `must not be blank`, and a `PATCH` with `phone: ""` clears the phone (200) rather than keeping it.                                                      |
| `METHOD_NOT_ALLOWED` (405)                                                       | Any `/api/v1` route with a verb it does not serve (`DELETE /api/v1/models`), and any verb but `POST` on `/api/v1/mcp`; `Allow` lists the verbs served.                                                                                                                                                                                                       |
| `IDEMPOTENCY_KEY_REUSED` (409)                                                   | `POST /api/v1/automations/{name}/runs` twice with the same `Idempotency-Key` and a different `input`: the first answers 202, the second 409 and starts nothing. The same body again answers 202 `duplicate: true` with the first run's id.                                                                                                                   |
| `RUN_ACTIVE` (409)                                                               | `DELETE /api/v1/runs/{runId}` (or the project form) on a run whose status is `queued`, `running` or `waiting`; cancel it, then the delete answers 204 and the read 404.                                                                                                                                                                                      |
| `AUTOMATION_VERSION_UNKNOWN` (404) on a read                                     | `GET /api/v1/automations/{name}?version=99` on an automation that exists, or `?version=deployed` while nothing is deployed; an unknown automation answers `AUTOMATION_NOT_FOUND` instead.                                                                                                                                                                    |
| `AUTOMATION_TRIGGER_INVALID` (400) for an event                                  | `PUT /api/v1/automations/{name}/triggers` with `{"kind": "event", "event": "no.such.event"}` or a reserved name (`task.assigned`); the sentence lists the events the platform raises. Nothing is saved.                                                                                                                                                      |
| `AUTOMATION_INPUT_INVALID` (400)                                                 | `POST …/runs` with an input the automation's `inputs` schema refuses (`{"input": null}` against `{"type": "object"}`); `data.issues` names each field. No run exists.                                                                                                                                                                                        |
| `AUTOMATION_PROJECT_FORBIDDEN` (403) on the webhook door                         | `POST /api/projects/{id}/automations/webhook/{token}` with a project id that does not exist, is archived, or where the automation is not installed — one body for all three, naming neither the case nor the automation.                                                                                                                                     |
| `RATE_LIMITED` (429) on the webhook door                                         | 241 deliveries inside a minute from one address (before the token is checked), or 41 to one trigger; `Retry-After` names the wait.                                                                                                                                                                                                                           |
| `INVALID_BODY` for a NUL byte (400)                                              | Any REST write whose JSON carries `\u0000` in a string; `data.issues` names the field. Used to be a 500 from Postgres.                                                                                                                                                                                                                                       |
| `SKILL_EXISTS` (412)                                                             | `PUT /api/v1/skills/{slug}` with `If-None-Match: *` on a slug that already has a bundle; nothing is written, and the same body without the header updates it in place.                                                                                                                                                                                       |
| `INVALID_SKILL_SLUG` (400) naming the rule                                       | `PUT /api/v1/skills/<100 letters>` — the sentence says "at most 64", not the charset, and echoes at most 64 characters; `PUT /api/v1/skills/claude` says the name is reserved. `GET` and `DELETE` on the same slugs answer 404 `SKILL_NOT_FOUND` instead.                                                                                                    |
| `INVALID_BODY` on a skill body (400)                                             | `PUT /api/v1/skills/{slug}` with a `body` over 507,893 bytes of UTF-8 (a character count under the cap still counts), with an unknown key such as `slug`, or with `visibility: "private"` — the option list names `team` and `org` only.                                                                                                                     |
| `CONVERSATION_SOURCE_NOT_FOUND` (404) / `INTEGRATION_NOT_OWNED` (403) on a claim | `POST /api/v1/conversations/deliveries/claim` with a `source` no snapshot ever named, or one only another API key user's snapshots named; a source of your own answers 200 with its (possibly empty) deliveries.                                                                                                                                             |
| `DELIVERY_NOT_FOUND` vs `ATTACHMENT_NOT_FOUND` (404)                             | `GET /api/v1/conversations/deliveries/{id}/attachments/0` with an id nobody claimed answers the first; a claimed delivery with fewer attachments than the position — or a position such as `abc`, `-1`, `1.5` — answers the second.                                                                                                                          |
| Deleted snapshot at the stored version (200, not 409)                            | `POST /api/v1/conversations/sync` with `deleted: true` and the source's current `version` (the maximum `9007199254740991` included) closes the mirror; a second one replays as `applied: false`.                                                                                                                                                             |
| `INVALID_SESSION` (400) on a browser-session import                              | `POST /api/v1/browser-sessions/import` (as an allowlisted operator) with `domain: "localhost"`, `127.0.0.1`, `../etc/passwd` or `*.example.com`; `HTTPS://Example.COM/path` is accepted and stored as `example.com`.                                                                                                                                         |
| `BROWSER_SESSION_NOT_FOUND` (404)                                                | `DELETE /api/v1/browser-sessions/{id}` twice as an allowlisted operator: 204, then 404. A non-allowlisted key gets the 403 before any body or id is looked at.                                                                                                                                                                                               |
| `invalid_token` on OIDC userinfo (401 + `WWW-Authenticate: Bearer`)              | `GET /api/auth/oauth2/userinfo` with an expired or made-up bearer token. The token endpoint answers an unknown grant as `unsupported_grant_type`.                                                                                                                                                                                                            |
| `ORG_SLUG_REQUIRED` (400) on a read                                               | Any `/api/v1` read — `GET /api/v1/contacts`, say — with a key whose user belongs to two organizations and no `X-Organization-Slug`; the dashboard's last-opened organization never answers a machine call; the 400 lists the slugs under `data.organizations` (`GET /api/v1/me` answers them too once one is named). A single-organization key never sees this. |
| `ORG_SLUG_INVALID` (404) vs `ORG_FORBIDDEN` (403)                                 | `X-Organization-Slug: no-such-org` (or a value no slug can be, such as `Acme Inc` or 200 characters — echoed at most 64) answers 404 on every method; a slug of an organization the key's user is no member of, or is disabled in, answers 403 naming the slug. Both before any body is read.                                                                |
| `BODY_TOO_LARGE` (413)                                                            | Any REST write with a body over 1 MiB (`POST /api/v1/contacts` with a 2 MiB `metadata`), or over the route's own cap (a document's inline `content` 32 MiB, contacts bulk 8 MiB, a conversation snapshot 8 MiB, a staged upload 30 MiB, a skill save 4 MiB); a declared `Content-Length` past the cap is refused before a byte is read. The envelope carries `requestId`. |
| `INVALID_BODY` for bytes JSON cannot carry (400)                                  | Any REST write whose body is not UTF-8 (`printf '{"name":"\xff"}'`) — `The body is not valid UTF-8`; or whose JSON carries a whole number beyond 2^53 − 1 (`{"externalId": 12345678901234567890}`) — the issue names the key and says to send it as a string. Neither is rounded or repaired.                                                                |
| `INVALID_LIMIT` (400)                                                             | Any list with `?limit=2.5`, `?limit=abc` or `?limit=1e2`: the sentence promises a whole number and names the range. `?limit=0` and `?limit=9999` are clamped, not refused, and `?limit=` reads as the default.                                                                                                                                               |
| `INVALID_QUERY` on a list or a write (400)                                        | `GET /api/v1/contacts?statuss=active` (a parameter the route does not take — `data.issues` names it), `?limit=1&limit=100` (given more than once), `?status=` on a filter (`must not be blank`), `?foo=1` on a lookup such as `GET /api/v1/me`; and any query string at all on a write — `DELETE /api/v1/contacts/{id}?force=true` refuses instead of ignoring `force`. |
| `INVALID_CURSOR` (400)                                                            | `GET /api/v1/contacts?cursor=abc`, a cursor edited by one character, or a cursor another list answered (a products cursor on the contacts list); the position is never guessed and the first page is never answered in its place.                                                                                                                            |
| `INTERNAL_ERROR` (500) carries `requestId`                                        | Not provoked deliberately; when it shows up, the envelope's `requestId` equals the response's `X-Request-Id` (your own, when you sent one) and is what to quote. Every response, an error included, carries `X-Request-Id`.                                                                                                                                  |
| 431 at the edge (no envelope)                                                     | A request line or header block past 32 KiB through the proxy (a 40 KiB `X-Organization-Slug`, or a 40 KiB query string) answers 431 as plain text from Caddy, never JSON; straight at the node server the cap is 64 KiB. Below the cap, a 1 KiB slug is `ORG_SLUG_INVALID` with the echo cut at 64 characters.                                               |
| `OBJECT_STORE_UNAVAILABLE` (503) on a download                                     | `GET /api/v1/projects/{id}/files/{documentId}/content` (or its `HEAD`) while the object store is unreachable — stop the dev MinIO, or point `OBJECT_STORE_*` at a closed port — answers 503 with `Retry-After: 5`; the file's metadata (`GET …/files/{documentId}`) still answers 200, and a document that has no blob or belongs to another project is `FILE_NOT_FOUND`, never 503. |

## Must never appear

An unhandled rejection, a React error boundary, a raw backend validation error
rendered as a toast, or any `error`-level console line not on the known-benign
list in [`not-a-finding.md`](not-a-finding.md). There is no repro by definition;
any sighting is a finding.
