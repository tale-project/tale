# Error-surface provocation map

Which error each surface can produce, and how to reach it deliberately. Used by
the suites when a box says "expect the error state", and as the checklist for
"should this even be reachable from here?".

Add a row when a new error becomes reachable, with the shortest path that
provokes it and the recovery the surface offers.

## Reachable from the UI

| Surface                                                                               | How to reach it                                                                                                                                                                                                                                                                              |
| ------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Sandbox limits exceed deployment capacity (`sandboxes.limits.totalExceedsDeployment`) | In Settings > Sandboxes, edit the four limits so their total exceeds deployment capacity. The total and error update; saving stays blocked until the total fits. If the operator lowers capacity after the page loads, saving also catches the new limit.                                   |
| Sandbox deployment capacity unavailable (`sandboxes.limits.capacityUnavailable`)      | In a disconnected sandbox-service test stack, raise a limit in Settings > Sandboxes so the total grows. The page explains that lowering still saves and that infrastructure data must be refreshed before raising; reconnect and use Refresh. Lowering a limit in that state saves normally. |
| Sandbox limits exceed capacity with devices (`sandboxes.limits.totalExceedsCapacity`) | With a device online in Settings > Sandboxes, edit the four limits so their total exceeds the deployment capacity plus the device's sandboxes. The message names both parts of the ceiling; saving stays blocked until the total fits. |
| Connect command could not be created (`sandboxes.devices.addDialog.generateFailed`) | Open **Add device** while 20 connect commands of the organization are still unused and unexpired (or with the backend unreachable). The dialog offers **Try again**; nothing is written. |
| Device hub not configured (`sandboxes.devices.hub.notConfigured`) / unavailable (`sandboxes.devices.hub.unavailable`) | Run the spawner with `SANDBOX_HUB_PORT=0` (not configured: **Add device** is disabled) or stop it (unavailable: the registered devices stay listed without live state). |
| Custom provider endpoint refused (`settings.providers.custom.errors.endpointNotPermitted`) | In Add credential > Custom provider, submit a base URL on a private or loopback host (`http://10.0.0.5:8000/v1`) on a deployment without `TALE_ALLOW_PRIVATE_PROVIDER_HOSTS=1`. The dialog keeps the form and shows the refusal; neither the definition nor the credential is written. |
| Custom provider base URL answers without a model list (`settings.providers.custom.errors.catalogNotJson`, `settings.providers.custom.errors.catalogNotFound`; backend `PROVIDER_CATALOG_NOT_JSON` / `PROVIDER_CATALOG_NOT_FOUND`) | Add a custom provider with **Discover from the endpoint** and the base URL `https://openrouter.ai` (its `/models` is a web page: `catalogNotJson`) or `https://api.openai.com` without `/v1` (404: `catalogNotFound`), any key. The credential row, **Check models** and **Refresh catalogs** all show the sentence; the listing is asked once, not retried. Setting the base URL to the API root (`…/v1`) clears it on the next listing (SET-B40). |
| Provider model listing unreachable, key refused or failing (`settings.providers.custom.errors.catalogUnreachable`, `settings.providers.custom.errors.catalogKeyRefused`, `settings.providers.custom.errors.catalogUpstreamError`, each with `settings.providers.catalogs.failureDetail`; backend `PROVIDER_CATALOG_UNREACHABLE` / `PROVIDER_CATALOG_KEY_REFUSED` / `PROVIDER_CATALOG_UPSTREAM_ERROR`) | Add a custom provider with **Discover from the endpoint** and the base URL `https://api.openai.com/v1` with a wrong key (401: `catalogKeyRefused`, asked once), or `https://example.com:81/v1`, where nothing answers (`catalogUnreachable`, asked again until the attempts run out); an endpoint whose `/models` answers HTTP 5xx, such as a stand-in server, gives `catalogUpstreamError` and is asked again too. The credential row and **Refresh catalogs** show the sentence with the server's words in parentheses, **Check models** the sentence alone, and the MCP `provider` refresh refusal's hint names the fix (SET-B47). Any other listing failure reads `settings.providers.custom.errors.catalogUnavailable`; its cause is only in the backend log. |
| Custom provider version conflict (`settings.providers.custom.errors.versionConflict`, backend `CONFIG_VERSION_CONFLICT` 409) | Open **Edit credential** for the same custom provider's credential in two tabs, save in one, then save in the other (SET-B21). The second save is refused and writes neither the provider nor the credential; its dialog stays open, and reopening it loads the current facts. `POST /api/app/provider-credentials/{id}/with-definition` answers the code when either `expectedHash` (the credential's, or the definition's) is no longer current. |
| HTTP step failures (`automationRuns.reasons.HTTP_*`) | Run live an `http.get` step on `https://httpbin.org/status/404` (`HTTP_STATUS`), on `http://169.254.169.254/latest` (`HTTP_BLOCKED_HOST`), on `https://httpbin.org/delay/10` with `timeoutMs: 2000` (`HTTP_TIMEOUT`), or with a credential on an address outside its base URL (`HTTP_OFF_ORIGIN`). The run page's failure card names the cause and the fix; `okStatuses: [404]` lets the 404 through as an answer. |
| Knowledge search and usage-limit step failures (`automationRuns.reasons.KNOWLEDGE_*`, `automationRuns.reasons.BUDGET_EXCEEDED`) | In an organization with no embedding model (Settings › Data residency), run live a `knowledge.search` step (`KNOWLEDGE_NOT_CONFIGURED`); point the embedding model at a provider credential whose key is revoked (`KNOWLEDGE_UNAVAILABLE`); set a project's monthly cost limit to the smallest amount, use it up, then run live a `knowledge.search` or an `llm` step in that project (`BUDGET_EXCEEDED`). |
| Task creation step failures (`automationRuns.reasons.TASK_*`) | Run live a `task.create` step with an assignee no member or agent answers to (`TASK_ASSIGNEE_UNKNOWN`), or in a project its automation is not installed in (`TASK_PROJECT_NOT_BOUND`). |
| Custom provider credential name taken (the server's sentence, backend `CREDENTIAL_NAME_TAKEN` 409) | In **Edit credential** for a custom provider's credential, change the **Base URL** and give the credential the name another credential of the provider carries (SET-B21). The dialog keeps the form and shows the server's sentence; the provider keeps its Base URL and name, and so does the credential. |
| Automation version conflict (`automations.detail.staleVersion.title`, backend `AUTOMATION_VERSION_STALE`) | Open one automation's workbench in two tabs, save a version in one, then save a draft in the other. The second save is refused with a dialog naming the version that landed; **Discard my changes and reload** shows it, **Save anyway** appends on top of it. The editor sends a base version, and so does an MCP `save_automation` that names `baseVersion` (see the MCP row below); an upload and a save without one still append last-write-wins. |
| Product image refused for what it carries (`products.edit.imageActiveContent`, backend `PRODUCT_IMAGE_ACTIVE_CONTENT`) | In Products > Add product > Basics, upload an SVG with a `<script>` element, an `on*` attribute or an external reference. The message sits under **Image** and in a toast; a passive SVG or a raster image uploads. Bytes that are no image at all answer `PRODUCT_IMAGE_INVALID` (`products.edit.imageUnsupported`); a file over 5 MiB `FILE_SIZE_INVALID` (`products.edit.imageTooLarge`). |
| Import rows refused (`common.import.rowErrorsTitle`, backend `INVALID_BODY` per row) | Import a products or contacts file with an empty name/email, `notanumber` in a numeric column, an unknown currency or status, or a duplicate email. The dialog lists each refused line with its first issue; the other rows land. The app bulk doors answer 200 with `errors[].index` at the sent position and `issues[]` naming the field, the REST contacts-bulk shape. |
| Embedding credential in use (`settings.providers.credential.inUseByEmbedding`, backend `CREDENTIAL_IN_USE` 409 with `data.usedBy: ["embedding"]`) | In Settings > AI providers, delete the credential the embedding model is saved on (or that provider's active default while the model uses the provider default — siblings do not count, nothing promotes one). The dialog warns first (`settings.providers.credential.deleteEmbeddingWarning`, fed by `GET /api/app/provider-credentials/{id}/dependents`); the delete answers the toast and nothing is removed. Disabling that credential, or unticking its **Default** in the edit dialog, answers the same code (`settings.credentials.updateFailed`). |
| Embedding credential missing (`settings.dataResidency.orgEmbedding.statusCredentialMissing`; indexing `embedding_provider_refused`) | Remove the embedding model's credential row behind the app's back (see DATA-B7). Data residency shows **Credential missing**; a new upload fails at once naming Settings → AI providers; REST knowledge search answers 409 `EMBEDDING_CREDENTIAL_REJECTED`; the chat assistant says the credential is missing rather than "not set up". Saving the fix — a credential the embedding model resolves in Settings > AI providers, or another credential under **Embedding model** — re-queues the failed upload by itself. |
| Embedding providers unchecked (`settings.dataResidency.orgEmbedding.supportReadFailed`, `settings.dataResidency.orgEmbedding.modelUnchecked`) | Block `/api/app/knowledge/embedding/recommendations` in DevTools → Network and reload Settings > Data residency (DATA-B9). The **Embedding model** form refuses every provider — no model field, header Save off — and offers **Try again**; nothing is written until the check answers. |
| Embedding provider cannot embed (`settings.dataResidency.orgEmbedding.errors.providerUnsupported`, backend `EMBEDDING_PROVIDER_UNSUPPORTED` 400) | The form refuses such a provider before any save (**Cannot embed**), so the code reaches it only when the declaration changed after the page loaded: with the page open and an organization-defined provider chosen, add `embedding: unsupported` to its `$TALE_CONFIG_DIR/<org>/providers/<name>.yml`, then Save. The sentence sits under **Model**, without a toast. `POST /api/app/knowledge/embedding` naming Anthropic answers the code directly (DATA-B9). Nothing is written. |
| Custom provider identifier reserved (`settings.providers.custom.errors.nameReserved`) | Only reachable when a shipped provider appeared after the page loaded its catalog (an image upgrade mid-session); the dialog otherwise numbers the identifier past every provider it can see. |
| Deleted automation (`automations.detail.deleted.banner`, backend `AUTOMATION_DELETED` 404 with `data.deletedAt`) | Delete an automation that has runs, then open one of its run URLs (AUTO-F49). The app door `GET /api/app/automations/{name}` answers the tombstone's date; the Runs pages render under the banner. Not answered on REST v1, whose `GET /automations/{name}` keeps `AUTOMATION_NOT_FOUND`. |
| Missing automation version (`automations.editor.versionNotFound.title`, backend `AUTOMATION_VERSION_UNKNOWN` 404 with `data.latestVersion`) | Open an existing automation's editor with `?version=99` (a number it never saved). The editor keeps the automation's tabs and shows "Version 99 doesn't exist" with **Open latest**; an unknown slug still answers the plain `automation not found` 404 and the automation-level empty state. |
| Organization delete without its name (`settings.organization.deleteConfirmNameMismatch`, backend `ORG_CONFIRM_NAME_MISMATCH` 400) | `POST /api/app/organizations/{id}/delete` with no `confirmName`, or one that is not the organization's name (trimmed, case-insensitive). The UI never sends it: the **Delete organization** confirm keeps its button disabled until the name is typed exactly. Nothing is written; the hold gate is not even reached. |
| Organization delete preserves unresolved automation holds (`settings.organization.deleteBlockedByLegacyAutomation`, backend `ORG_LEGACY_AUTOMATION_HELD` 409) | In an isolated upgrade fixture, preserve an active pre-protocol automation run through migration 0163. As an owner, send `POST /api/app/organizations/{id}/delete` with the correct `confirmName`. The organization is preserved before audit or cleanup work starts. A stop request leaves this refusal in place; there is currently no hold-release action. |
| Team name taken (`settings.teams.teamNameTaken`, backend `TEAM_NAME_TAKEN` 409) | In Settings > Teams, create a team whose name another team of the organization already reads as — `finance ` beside `Finance` — or rename one onto such a name via **Edit**. The sentence sits under **Team name**, the dialog stays open and nothing is written; re-saving a team's own name (in any case) goes through. SCIM answers the same rule as a 409 `uniqueness` on a Group's `displayName`. |
| Archived project refuses a write (`projects.errors.PROJECT_ARCHIVED`, `tasks.errors.PROJECT_ARCHIVED`, backend `PROJECT_ARCHIVED` 403) | Archive a project on **General**, then race a write against it: keep a second tab open on its Agents tab from before the archive and submit **New agent**, or **Create task** from a stale board, or drop a file on its stale Files tab — or delete / detach one of its files, comment on one of its tasks, save a secret on its stale Secrets tab, or bind it to an automation / start a run in it. The toast names the archived project; the fresh page hides every write control and shows the **This project is archived** banner; the banner carries no action — **Restore** (`projects.rowActions.restore`) is on **General** for admins. |
| Folder rename in a synced tree refused (`documents.folder.renameSyncManaged`, backend `FOLDER_SYNC_MANAGED` 409) | The row menu offers no **Rename** for a folder at, inside or above a synced folder. To reach the refusal, open **Rename** on a parent folder, start syncing a folder below it from another tab, then submit. The dialog keeps the name and names the rule on the field; nothing is renamed. |
| Mention directory unavailable (`common.errors.generic` toast, backend `MENTION_DIRECTORY_UNAVAILABLE` 503) | Post a task comment, create a task, or save a task description whose text carries an `@` token while one leg of the mention directory cannot be read (the members, the deployed automations or the project's agents). No healthy stack reaches it from the UI; `checkCollabMentions` and `checkTaskDescriptionMentions` in `backend:integration` provoke it by failing the agents leg. Nothing is saved and no one is notified; the composer, the **Create task** dialog and the description editor keep the typed text for a retry. An edit that adds no `@` token reads no directory, so it never answers this. |
| Reviewer refused (`tasks.reviewer.invalid`, backend `TASK_REVIEWER_INVALID` 400) | Open **Reviewer**, then remove a listed person's project edit access or remove a listed project agent in another session before choosing them (PROJ-B9). The typed `POST /api/app/tasks/{taskId}/reviewer` also refuses an agent from another project. One localized toast explains the eligible choices; the current reviewer and pending review stay intact and the field reloads. The legacy `reviewerUserId` update can still answer `TASK_REVIEWER_NO_EDIT_ACCESS` 400, rendered as `tasks.reviewer.editorsOnly`. |
| Reviewer agent lacks the review grant (`tasks.reviewer.agentPermissionRequired`, backend `TASK_REVIEWER_PERMISSION_MISSING` 400) | The picker greys a project agent without **Review other agents’ task results** and names the missing permission (PROJ-B13), so reach the refusal with a stale list: open **Reviewer** with a granted agent listed, revoke that grant on the project's Agents tab in another session, then choose the agent. The typed `POST /api/app/tasks/{taskId}/reviewer` answers the same code for **Project default** when the project's default agent lost the grant. One localized toast names the permission; the current reviewer and pending review stay intact and the field reloads. |
| Project review default changed (`projects.taskReview.stale`, backend `PROJECT_REVIEWER_STALE` 409) | Make different **Default reviewer** drafts on **General** in two sessions, save one, then save the older draft (PROJ-B12). The stale save writes nothing and retains the draft with one localized failure. Discard it and reload the current default before choosing again. Existing pending reviews never move with this setting. |
| Project review default unavailable (`projects.taskReview.unavailable`, backend `PROJECT_REVIEWER_INVALID` 400) | Choose an agent under **Default reviewer**, remove that agent in another session, then save. The draft stays visible and the saved default stays intact. Reload and choose a remaining project agent or **Person**. An agent from another project reaches the same refusal, including a repeated selection of a now-deleted default; an agent without the task review grant answers `PROJECT_REVIEWER_PERMISSION_MISSING` instead. |
| Project review default lacks the review grant (`projects.taskReview.permissionRequired`, backend `PROJECT_REVIEWER_PERMISSION_MISSING` 400) | Under **Default reviewer** choose a project agent without **Review other agents’ task results** — the draft already shows the permission caption — then save. The draft stays visible and the saved default stays intact; the one localized failure names the permission. Grant the tool on the project's Agents tab, or choose another agent or **Person**. A repeated selection of a default whose grant was revoked answers the same code. |
| Legacy reviewer administration (`RBAC_FORBIDDEN` 403) | As a Member who owns a task, send a different `reviewerUserId` or `null` through `POST /api/app/tasks/{taskId}`. Project edit access is required; no reviewer, notification or activity changes. Ordinary own-task edits still succeed, including an unchanged reviewer field. Public REST PATCH has an archive-only body and already rejects this field with 400. |
| Task review handoff changed (`tasks.reviewer.stale`, backend `TASK_REVIEWER_STALE` 409) | Open one pending review in two sessions, hand it to a reviewer in one, then submit the other's old selection (TASK-B39). A changed approval, source run, captured recipient or task reviewer also makes that expected state stale. One localized toast and a refetch show the winner; no second handoff, execution or status change occurs. Read the current review before choosing again. |
| Task review handoff busy (`tasks.reviewer.busy`, backend `TASK_REVIEWER_BUSY` 409) | In an isolated fixture, give an **In review** task a live run or protected question, then try handing its pending review to an agent. The review stays with its current recipient. Resolve the existing work or question through its own controls, then read the task again before a handoff. |
| Task review source missing (`tasks.reviewer.sourceRequired`, backend `TASK_REVIEW_SOURCE_REQUIRED` 409) | Move a task with no completed native implementation run into **In review**, then try to transfer that pending review to an agent. An obsolete or unsettled source run is also refused. Choose an eligible person for that result; a display name or current assignee cannot stand in for the actual source run. |
| Changed implementation (`tasks.reviewer.sourceChanged`, backend `TASK_REVIEW_SOURCE_CHANGED` 409) | With a captured native review, change its implementation assignee and try an explicit transfer to another agent. The review remains captured; restore the original implementation assignee or hand it explicitly to an eligible person. `pendingReview.agentReviewBlockedReason` reads `source_changed`. |
| Human-policy handoff (`tasks.reviewer.humanPolicy`, backend `TASK_REVIEWER_HUMAN_REQUIRED` 409) | Enable human independence or required competences in the isolated organization and try transferring a pending human review to an agent. It refuses rather than silently changing the requested recipient. New reviews already follow the human chain; captured agent reviews show `human_policy` until explicit transfer. |
| Unavailable review policy on approval (`tasks.reviewer.policyUnavailable`, backend `TASK_REVIEW_POLICY_UNAVAILABLE` 409) | In an isolated organization, make `review_policy` unreadable or invalid, then approve a human-owned pending review from task Status, the subject panel, or a board drag to Done. One localized refusal explains that valid organization policy must be restored. The strict gate also refuses native `task_review` verdicts and human approval after an agent-to-person transfer; a cached policy or the transfer cannot authorize approval. Human request-changes and withdrawal keep their existing behavior. |
| Unavailable review policy (`tasks.reviewer.policyUnavailable`, backend `GOVERNANCE_POLICY_UNAVAILABLE` 409 on handoff) | Make the isolated review policy invalid or unavailable. Native settlement retains its configured agent and records the result; the read reports `policy_unavailable`. An explicit agent handoff refuses. Restore valid policy before deciding. A transfer to an eligible person alone does not make approval possible while the policy is unavailable. |
| Task reviewer is the implementer (`tasks.reviewer.notIndependent`, backend `TASK_REVIEWER_NOT_INDEPENDENT` 409 on handoff) | The picker disables the actual implementation agent (TASK-F63). Provoke a stale choice in an isolated fixture by changing the source after the list loads, or submit that agent through the app handoff door. No ownership changes; choose another project agent. Changing the task's assignee does not change who implemented the recorded result. |
| Agent-owned review cannot be approved by a person (`tasks.reviewer.agentRequired`, backend `TASK_AGENT_REVIEW_REQUIRED` 409) | On a task whose pending review belongs to an agent, try the human **Done** status action. The task remains **In review** with the same pending review. Let the assigned independent agent decide, or explicitly hand the review to an eligible person before that person approves it. |
| Connector Reconnect target gone (server page "This credential cannot be reconnected", 404; flow error `credential_missing`) | Start **Reconnect** on an OAuth row and delete that row from a second tab while the vendor's consent screen is open, then consent (CONN-B7); or open the start door with a `credentialId` that is empty, unknown, another organization's or another connector's (CONN-B8). Nothing is saved; a Reconnect in the row's own workspace renews it, and **Add credential** connects the other workspace as its own row. |
| App sign-in refused (backend `CREDENTIAL_APP_REFUSED`; the step or sync shows `no usable credential for outlook: Credential "…": the "outlook" token endpoint refused the app's sign-in (invalid_client) — check …`, not the code) | Replace an Outlook **App sign-in** credential's client secret with a wrong one, then run the mail sync or any Outlook action (CONN-B13). | Connector consent settings refused (server page "These settings cannot be used for this connection", 400; flow error `invalid_settings`) | Open a **Connect** start link whose `config` the connector does not take (`{"region":"eu"}` for Outlook, any settings for Slack), is not JSON, or rides a Reconnect (CONN-B15). No consent screen opens and nothing is saved; the page is localized and links back to connector settings. |
| Connector start link opened from another site (server page "Start this connection in Tale", 403; flow error `cross_site_start`) | Click a **Connect** or **Reconnect** start URL from a page of another site while signed in as an Admin (CONN-B16), or send it with `Sec-Fetch-Site: cross-site` and the session cookie. No consent screen opens and nothing is saved; the page is localized and links back to connector settings. The same URL typed into the address bar, or **Connect** in Tale, starts the consent. |

The code is never redeemed and nothing is saved. |
| Standard agent switched off (`tasks.agentRun.standardAgent.switchedOff`, backend `STANDARD_AGENT_OFF` 403) | With a task already given to a project's standard agent, turn off **Provide a standard agent** under Governance > Models (GOV-F52), then **Start agent** on the task. ## Reachable on the API surface only

Never a rendered message — seeing one of these in the UI is itself a bug.

| Failure                                                                          | Where it shows up                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| -------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

## Must never appear

An unhandled rejection, a React error boundary, a raw backend validation error
rendered as a toast, or any `error`-level console line not on the known-benign
list in [`not-a-finding.md`](not-a-finding.md). There is no repro by definition;
any sighting is a finding.

## Agent run diagnostics

These bounded diagnostics belong to the failed agent node or task run when a
vision polyfill is required. A serving model proven to support native vision
retains its direct image-reading path without consulting the polyfill policy.
Diagnostics do not contain provider responses, endpoint values or credentials.
Correct the configuration or restore the service, then explicitly retry the run.

| Failure                           | Provocation and recovery                                                                                                                                                                                                                                                     |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `VISION_MODEL_POLICY_INVALID`     | Supply a malformed `vision_model` policy for a text-only or unknown serving target in an isolated test. Configure both `providerSlug` and `modelId`, or explicitly choose Auto. No polyfill is selected before this refusal.                                                 |
| `VISION_MODEL_POLICY_UNAVAILABLE` | Make the policy read fail, corrupt its stored file, or remove access to the configured root/organization. Restore valid governance configuration; a real absent policy file in an available root still means Auto, but a cached earlier value cannot bypass this fresh read. |
| `VISION_MODEL_UNAVAILABLE`        | Pin a missing/non-vision model, remove its provider or active gateway credential, or exclude it from the credential allowlist. Restore the exact pin's serving prerequisites. A text-only turn cannot substitute another provider or proceed without the required polyfill.  |
| `VISION_MODEL_RESOLUTION_FAILED`  | Make the explicitly pinned provider, credential or catalog resolver fail. Restore that service and retry; its private response is not copied into the diagnostic.                                                                                                            |

## Task run failures

A project agent's run on a task that fails for good — its automatic retries
spent, or a failure no retry changes — leaves the task at In progress. While the
task is still assigned to that agent, the top of the task shows **The agent
couldn't finish this task** (`tasks.agentRun.failureTitle`) and the sentence of
the failure's class (`tasks.agentRun.failure.*`), picked from the code stored
on the run (`lib/shared/task-run-failure.ts`); neither the code nor the run's
own words appear there. **View** (`common.actions.view`) on the run's row in
the task's conversation shows **What the run reported**
(`tasks.agentRun.reported`). **Retry** (`tasks.agentRun.retry`) shows to whoever
may start the agent. The person who started the run and the task's watchers who
can still open the project get **Agent run failed** (`inbox.agentRunFailed`),
also by email: four classes have a body of their own
(`inbox.agentRunFailedBudgetBody`, `inbox.agentRunFailedPolicyBody`,
`inbox.agentRunFailedSetupBody`, `inbox.agentRunFailedInputBody`), every other
class reads `inbox.agentRunFailedBody`. A failure that retries shows neither
while its retry is pending: the Run row reads **Auto-retry n of 3**
(`tasks.agentRun.autoRetrying`), and the notice comes once the last attempt
fails (TASK-B35).

A run has twelve hours from its start, waiting included. On a local stack only,
date that limit back, and the watchdog, which looks every two minutes, fails
the run with nothing retrying it (the task's id ends its page's address):
`docker exec tale-db psql -U tale -d tale_app -c "UPDATE app.project_agent_runs SET deadline_at_ms = 0 WHERE task_id = '<task id>' AND status IN ('queued', 'running')"`.
A setting of the sandbox service named below reaches only the sessions it
creates after the change: set it in that service's environment, recreate the
service, then **Destroy** the agent's workspace on
`/dashboard/{org}/settings/sandboxes` (or use a new agent), and put the setting
back afterwards.

| Failure | Provocation and recovery |
| --- | --- |
| `tasks.agentRun.failure.budget` (`budget_exceeded`) | A cost rule that binds the person who starts the run and is already reached: a **User** rule at **Max cost** below what they spent this month, then **Start agent** (TASK-F57, TASK-B5); a cap reached during the turn ends the run the same way. No automatic retry; the bell's body is `inbox.agentRunFailedBudgetBody`. Raise or delete the rule, then **Retry**. |
| `tasks.agentRun.failure.policy` (`policy_refused`) | A guardrail under **Governance** that blocks a word, and the project's standard agent started on a task whose description holds it (TASK-B53). No automatic retry; the bell's body is `inbox.agentRunFailedPolicyBody`. Remove the word or the guardrail, then **Retry**. |
| `tasks.agentRun.failure.setup` (`equipment_missing`, `agent_model_missing`, `agent_deleted`) | Equip the agent with a skill, delete the skill or stop sharing it with the project, then **Start agent** → `equipment_missing`. A model the agent names that its provider no longer serves gives `agent_model_missing`; an agent deleted under its waiting run gives `agent_deleted`. No automatic retry; the bell's body is `inbox.agentRunFailedSetupBody`. Fix the agent on the project's Agents tab, then **Retry**. |
| `tasks.agentRun.failure.input` (`input_missing`) | Attach a file to the task, delete its object from the object store behind Tale, then **Start agent**: the start fails, and **View** names the file. No automatic retry; the bell's body is `inbox.agentRunFailedInputBody`. Remove the attachment or upload it again, then **Retry**. |
| `tasks.agentRun.failure.time_limit` (`deadline`) | A run still working twelve hours after its start; on a local stack, the update above while the agent works. No automatic retry. Split the task, or **Retry**. |
| `tasks.agentRun.failure.capacity` (`park_deadline`) | A run still waiting twelve hours after its start for anything but its model — **Waiting for a worker**, **Waiting for room**, **Waiting for a workspace** or **Waiting for its sandbox** (TASK-B50, TASK-B58 and the refusals below); on a local stack, the update above while it waits. No automatic retry. Free a worker (**Manage agent workers**), then **Retry**. |
| `tasks.agentRun.failure.model_capacity` (`model_capacity`) | A run still **Waiting for model capacity** twelve hours after its start (TASK-B59); on a local stack, the update above while it waits. A model at capacity during a turn does not end the run for good: it waits again and spends no attempt. No automatic retry after the twelve hours; **Retry** later, or have an Admin check the provider. |
| `tasks.agentRun.failure.model` (`harness_error`, `empty_turn`, `credential_rotated`, `credential_cooldown`) | A harness that exits before its turn is done (TASK-B6: a Codex agent whose `CODEX_HOME` is missing), a provider that answers an error, or a turn that ends before its work. Retried three times; the notice and the bell come when the fourth attempt fails. `credential_rotated` and `credential_cooldown` come from a subscription broker — a token refreshed under the turn, every account cooling down after a rate limit — and their first retries spend no attempt. |
| `tasks.agentRun.failure.start` (`start_failed`) | Stop the sandbox service (`docker stop tale-sandbox`), then **Start agent**: each attempt fails to create its session. Retried three times; start the service again (`docker start tale-sandbox`), then **Retry**. |
| `tasks.agentRun.failure.interrupted` (`session_gone`, `turn_crashed`, `harvest_failed`, `steer_restart_failed`, `sandbox_capacity`) | Remove the agent's sandbox while it works (TASK-B35) → `session_gone`. Retried three times, each retry continuing the conversation; the notice comes after the last. A comment's restart its sandbox refuses for room ends as `sandbox_capacity` and retries after 15 seconds without spending an attempt (the refusals below). |
| `tasks.agentRun.failure.stalled` (`turn_stalled`) | Set `SANDBOX_EXEC_STALL_MINUTES=1` on the sandbox service, then give the agent a task that has it run `sleep 600`: the session ends a process that printed nothing and used almost no CPU for the window. No automatic retry; **View** shows what it printed last. The default window is 45 minutes, `0` turns it off. |
| `tasks.agentRun.failure.out_of_memory` (`resource_exhausted`) | Set `SANDBOX_AGENT_MEMORY` on the sandbox service below what the harness needs (`256m`), then **Start agent**: the session's memory limit kills the agent. Retried after 2, 10, then 30 minutes, however long each attempt worked; the notice and the bell come when the third retry runs out of memory too. Give agents more memory, then **Retry**. |
| `tasks.agentRun.failure.unknown` (no code, or one this build does not know) | A run failed before its code was stored, or by a newer build. On a local stack, give a failed run a code this build does not know and reload the task: `docker exec tale-db psql -U tale -d tale_app -c "UPDATE app.project_agent_runs SET failure_code = 'not_a_code' WHERE task_id = '<task id>' AND status = 'failed'"`. |

## Sandbox refusals that park a run

The sandbox service refuses to create a session, or to let a released one
resume work, with a busy answer and the seconds to wait; inside a session,
runnerd refuses a new process the same way. None of them fails a start: the run
waits, reading **Waiting for room** (`tasks.agentRun.waiting.host`) with
`tasks.agentRun.waitingWhy.host` in the Run row and the timeline, offers
**Cancel run** (`tasks.agentRun.cancel`), spends no automatic retry, and
starts by itself once there is room. Twelve hours after its start it fails as
`tasks.agentRun.failure.capacity`. Each setting below belongs to the sandbox
service, as the self-hosted environment reference describes it; put it back
after the box.

| Refusal | Provocation and recovery |
| --- | --- |
| `session_quota` | The deployment's session capacity is reached: set `SANDBOX_MAX_SESSIONS` below the sessions running, then **Start agent** (TASK-B50). The run starts once a session ends, or once the service stops a released idle session to make room. |
| `host_memory` | On a local Docker host with `SANDBOX_MAX_SESSIONS` unset, set `SANDBOX_MIN_FREE_MEMORY` to about the host's available memory, below its total (a reserve at or above the total keeps the service from starting), then **Start agent**. The service first stops a released idle session, then answers busy; the run starts once memory frees. |
| `host_cpu` | Under the `default` admission preset, set `SANDBOX_CPU_PRESSURE_PERCENT=1`, keep every CPU of the host busy (one `yes > /dev/null` per CPU) and start two agents at once: new sessions start one at a time, so the second waits for room until the first has started, about ten seconds. |
| `host_pressure` | Set `SANDBOX_ADMISSION_PRESET=conservative` and keep the host's load average at or above one per CPU (the same load), then **Start agent**: a start held back for load, memory or I/O pressure answers `host_pressure`. The project's dispatch holds its own starts on the same reading and says **The sandbox host is busy**. |
| `host_disk` | Set `SANDBOX_MIN_FREE_DISK` above the free space of the disk that holds the session workspaces, and `SANDBOX_CRITICAL_FREE_DISK=0` so that released sessions are not stopped, then **Start agent**. The service reclaims stopped unused build caches first, then answers busy; the run starts once the disk has room. |
| `session_memory_busy` (runnerd) | A session that still runs a process and uses 90 percent of its memory limit refuses the next one; an idle session never does, since what a turn leaves running ends with it. With `SANDBOX_AGENT_MEMORY` low, have the agent run a process that holds most of it and, while that turn works, comment on the task: the comment's restart is refused, and the run ends as `sandbox_capacity` (class `tasks.agentRun.failure.interrupted`) with a retry that spends no attempt, starts after the refusal's wait and then waits for room like any start. A start refused so reads **Waiting for room**, never **Waiting for its sandbox**. |

## Server transcription model routing

These bounded codes appear in model status and composer capability metadata.
The server dictation door returns 409 for a configuration refusal and 503 for
an unavailable policy/provider resolver. Browser speech recognition remains
independently available; video links can still use published captions.

| Failure | Provocation and recovery |
| --- | --- |
| `NO_TRANSCRIPTION_MODEL` | Choose Automatic with no active compatible default credential and transcription model. Configure one under AI providers, then retry the capability read. |
| `TRANSCRIPTION_MODEL_UNAVAILABLE` | Pin a removed model, disable its default credential, or exclude it from the credential allowlist. Restore that exact model or explicitly save another choice/Automatic; no substitute is called. |
| `TRANSCRIPTION_MODEL_POLICY_INVALID` | Store malformed YAML/JSON or a partial pin in an isolated test. Choose Automatic or a complete provider/model pair and save to repair it. |
| `TRANSCRIPTION_MODEL_POLICY_UNAVAILABLE` | Deny the policy read or make the org config root unavailable. Restore readable configuration; an absent file in an available root remains Automatic. |
| `TRANSCRIPTION_MODEL_RESOLUTION_FAILED` | Break provider catalog or credential resolution with no usable Automatic alternative, or break the pinned provider. Restore the service and retry; private responses and credentials never appear in the code. |
