Physical Safari/PWA scrolling remains `RESP-F22`.

A failed membership refresh over a loaded member context is not access still loading (#4859). `app/routes/dashboard/dashboard-layout.test.tsx` holds the ability-loading flag under the outlet (false through the failure, true on a first load from the last role and on a refetch that dropped its data), the shell's notice and its **Try again**, a Knowledge tab rendered through the failure, and the full-page error when nothing was loaded. `app/components/layout/access-refresh-notice.test.tsx` holds the busy retry, the repeated announcement and the focus handed to the page. A real backend failure, the browser layout and a screen reader remain `NAV-B20`.

A refused organization switch is not a switch (#4887). `app/routes/dashboard/switching.test.tsx` holds the switching page: a refusal (a `429` Better Auth answers instead of throwing) and a request that gets no answer each name the organization with their reason, record nothing and go nowhere; **Try again** switches and records once; an organization it cannot name, or a session in none, offers Home; a switch still running at `ORG_SWITCH_TIMEOUT_MS` says so and still goes on if it then succeeds, and an attempt **Try again** replaced no longer reports. `app/routes/dashboard/dashboard-layout.test.tsx` holds the same for the layout's sync of the session to its address (the refusal, **Try again**, the bound) in place of the switching spinner, and `app/lib/auth/set-active-organization.test.ts` the helper every caller shares. `app/features/organization/components/organization-list-panel.test.tsx` holds the switcher's roles in German and a list that cannot load, with **Try again**. A real refusal, the browser layout, the audit log and the wording in German and French remain `NAV-B21` and `NAV-B22`.

What's new neither spins without end nor calls release notes it could not read up to date (#4900). `app/routes/dashboard/changelog.test.tsx` holds the page over the real changelog hook and adapters: a changelog state that cannot be read (a `500` past the read's retries) still reads the feed, without `from`, and shows the current release; a feed that lists no release shows **We couldn't load release notes** with the link to GitHub, never **You're up to date.**; and a state that loads still reads the feed back to the version last seen. `app/hooks/use-changelog-notification.test.ts` holds the failed read with no dot and no toast. `backend/domains/changelog/service.test.ts` reads GitHub's page through the real parser: a first page that lists no release is an error, not an empty list, and the next visit asks GitHub again (`CLOG-R4`, `CLOG-R5`). A real change to GitHub's page and the browser layout remain `NAV-F8`.
