A `@tale/ui` component never receives its own labels as props. "Cancel",
"Loading content", "Search" and the rest live in the package's message catalog,
and the component reads them with `useT`. Your service merges that catalog under
its own at startup, which is why a button with no `children` still announces
itself in the reader's language.

By the end of this page you will know how to read a string, how the merge
resolves conflicts, and what a new key obliges you to do.

## Read a string with `useT`

```tsx
import { useT } from '@tale/ui/i18n/client';

function SaveButton() {
  const { t } = useT('common');
  return <Button>{t('actions.save')}</Button>;
}
```

`useT` is a thin wrapper over `react-i18next`'s `useTranslation`, scoped to one
namespace. Services usually re-export it with the namespace narrowed to their
own catalog, so a typo in the namespace is a type error rather than a blank
string.

## Merge the catalogs at startup

`initServiceI18n` builds the i18n instance your `AppShell` mounts:

```ts
import { marketingUiMessages } from '@tale/marketing-ui/i18n/messages';
import { initServiceI18n } from '@tale/ui/i18n/init-service';
import { uiMessages } from '@tale/ui/i18n/messages';

export const i18n = initServiceI18n({
  bundles: { en: enMessages, de: deMessages, fr: frMessages },
  // Vite requires the glob pattern to be a literal at the call site.
  regional: import.meta.glob('../../messages/*-*.yml', {
    eager: true,
    import: 'default',
  }),
  global: globalMessages,
  packages: [uiMessages, marketingUiMessages],
});
```

- **`bundles`** — your service's own catalogs, one per base locale.
- **`regional`** — regional overrides discovered by glob, e.g. `de-CH.yml`.
  Only files matching `xx-YY` are picked up.
- **`global`** — locale-neutral keys folded into every locale.
- **`packages`** — the catalogs of the packages you render.

The merge is **deep**, and package catalogs fold in **before** your service's,
so a service key always wins on a conflict — and it wins alone, without
dropping the sibling keys around it.

`uiMessages` itself is four bundles plus a global: `en`, `de`, `fr` and a sparse
`de-CH` override layered over `de`. It carries every string a `@tale/ui`
component renders, under namespaces like `common`, `search`, `themeSwitcher`,
`tables` and `toast`.

## Tell the test gate about the package catalogs

Each service gates its catalog with `defineI18nTests`. The `packageCatalogs`
option names the message directories merged at runtime, so a key your component
borrows from `@tale/ui` counts as defined and the missing-key check stays
honest:

```ts
import { defineI18nTests } from '@tale/ui/i18n/tests';

defineI18nTests({
  serviceRoot: path.resolve(HERE, '../..'),
  packageCatalogs: [
    path.resolve(HERE, '../../../../packages/ui/src/i18n/messages'),
    path.resolve(HERE, '../../../../packages/marketing-ui/src/i18n/messages'),
  ],
  modes: { 'usage-missing': 'enforce' },
});
```

Package catalogs feed the missing-key check only. They never feed the orphan
check — a package's own `messages.test.ts` owns that, so an unused key is
reported where it lives.

## Adding a key

Adding a key is a change to every locale, in the same commit. A key present in
one catalog and missing from another is a defect, not a follow-up.

1. Add it to `en.yml` under the right namespace.
2. Add it to **every** sibling locale — `de.yml`, `fr.yml`, and the regional
   overrides where the wording genuinely differs.
3. Reference it from code. The orphan check fails on a key nothing uses, and
   the missing-key check fails on a `t()` call with no key behind it.

Write each locale natively rather than rendering the English word for word: the
German catalog addresses the reader with *du*, the French with *tu*, and both
read like they were written first in that language.

ICU syntax is available for plurals and interpolation:

```yaml
results: '{count, plural, =0 {no results} =1 {# result} other {# results}}'
readingTime: '{minutes} min read'
```
