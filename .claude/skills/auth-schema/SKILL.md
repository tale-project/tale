# auth-schema

The Better Auth Convex tables are **generated** from the auth config, not hand-written. The Better
Auth CLI reads the static `auth` instance in
[`convex/betterAuth/auth.ts`](../../../services/platform/convex/betterAuth/auth.ts) (which is built
from the real config in [`convex/auth.ts`](../../../services/platform/convex/auth.ts) — plugins like
`organization`+teams, `twoFactor`, passkey) and emits the table definitions. Backend conventions
live in [`convex`](../convex/SKILL.md); auth-handling rules live in
[`security`](../security/SKILL.md).

## When this applies

Regenerate after **any** change that affects the auth data model:

- editing the plugin list / fields / `getAuthOptions` in `convex/auth.ts`,
- bumping `better-auth` or `@convex-dev/better-auth` in
  [`services/platform/package.json`](../../../services/platform/package.json),
- a Convex push or `bunx tsc --noEmit` that fails on a missing or renamed auth table — the generated
  schema has drifted from the config.

## The command

There is **no dedicated bun/npm script** for this — run the Better Auth CLI directly. `bunx` fetches
the `@better-auth/cli` package (the `better-auth` dep is already installed). From `services/platform`:

```bash
cd convex/betterAuth && bunx @better-auth/cli generate -y --output generated_schema.ts
```

This rewrites [`convex/betterAuth/generated_schema.ts`](../../../services/platform/convex/betterAuth/generated_schema.ts)
— the base `tables` (user, session, account, apikey, member, teamMember, …). It does **not** touch
anything else.

## Don't hand-edit the generated file

`generated_schema.ts` carries a "Do not edit this file manually" header — manual edits are lost on
the next run. Custom indexes and field overrides go in the sibling
[`convex/betterAuth/schema.ts`](../../../services/platform/convex/betterAuth/schema.ts), which spreads
the generated `tables` and layers on repo-specific extensions (the `apikey` field relaxations +
`suffix`, the `member`/`teamMember` composite indexes). Edit `schema.ts`, never `generated_schema.ts`.

## After generation

1. **Review the diff** — `git diff services/platform/convex/betterAuth/generated_schema.ts`. Confirm
   the table changes match the auth-config change you made; nothing else should move.
2. **Re-check `schema.ts`** — if a field you override (e.g. `apikey.configId`) was renamed or dropped
   upstream, fix the override so the spread still resolves.
3. **Regenerate Convex codegen** — `bunx convex codegen` (needs a live `CONVEX_DEPLOYMENT`) so
   `_generated`/`api.d.ts` reflect the new tables; see [`convex`](../convex/SKILL.md).
4. **Typecheck** — `bun run --filter @tale/platform typecheck` (`bunx tsc --noEmit`).
5. **Commit the generated file** alongside the config change — it's checked in, not built at runtime.
